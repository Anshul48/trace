TRACE: a document stream that files itself

TRACE is an experimental retrieval engine. It sorts a continuous stream of documents into a living, overlapping folder tree, so a brand-new arrival is searchable immediately — no full-index rebuild. Each question is routed down the few most promising branches instead of scoring everything.

The 30-second version

What: documents are cut into short passages (“atoms”), attached to groups (“leaves”) by similarity, and groups hang under topic hubs (“parents”) — an overlapping graph, not one rigid tree.

Why: new items become searchable the moment they arrive, without recomputing clusters over the whole corpus.

Proof: frozen run o94-scale10m over 10,003,381 tokens / 13,081 documents — guided recall@10 of 0.7367 (all-sources) and 0.4883 (leave-source-out), each against a matched flat baseline (0.055 / 0.0017) scoring the same rows.

Scope: a prototype evaluation protocol (all-sources vs disjoint-source), not a broad search-engine benchmark. No SOTA claims.

Run it yourself (mini path, verified 2026-10-18)

These exact commands were executed against a fresh extract of the seam12a tarball (Python 3.12). The environment lives inside the extracted directory. Example outcome on a small synthetic corpus: status PASS, 10,080 tokens / 36 docs / 72 atoms in ~25–40 s.

cd <extracted-seam12a-dir>
uv venv .venv --python /usr/bin/python3
uv pip install --python .venv/bin/python numpy==2.5.4 blake3==1.0.11
SUP_PYTHON=$PWD/.venv/bin/python bash runtime.sh tools/product_pilot.py --help

Mini engine run (up to 1M tokens on your own machine)

SUP_PYTHON=$PWD/.venv/bin/python bash runtime.sh tools/product_pilot.py \
  --tokens 10000 --profile local --source-root $PWD \
  --data-dir <your-data-dir> --out $PWD/out-mini \
  --drain-attribution --drain-census --holon-descriptor-columnar \
  --overrides-columnar --descriptor-matrix-all --per-view-sharing \
  --cold-scan-chunk 4096 --repair-columnar --candidate-source hnsw \
  --drain-bounded-k 32 --candidate-shadow-audit 8

Your --data-dir must hold docs-100m.jsonl (one JSON object per line, fields doc_id + text) plus an emb_cache/ directory in tl-gpu-embcache-v1 layout (384-dim float32 vectors). Only complete documents are ingested; cache misses are fatal. Non-VM runs are capped at 1M tokens (--profile local).

No one-click 10M reproduction today. A full 10M rerun has two blockers, both required: (a) the external 10M corpus (docs-100m.jsonl + embedding cache) is not shipped with the 1.2 MB source-only tarball; (b) --profile vm only runs on the host trace-build500 (hostname guard in tools/product_pilot.py). Scales of 100M–500M+ are roadmap, not measured.
