Verify

Check it yourself, from easy to thorough.

Each check below says what it proves and what it does not. The first needs only a browser. The last ones need Python 3 on your own computer.

1. Check a record in your browser Working today

Needs: a browser. About 20 seconds.

  1. Open a recorded search with the first record already open.
  2. Press “Check the fingerprint in my browser”.
  3. It should say the fingerprint matches.

What it proves: the text shown is exactly the text that was sealed in the library for that record. Your browser recomputes a SHA-256 fingerprint of the text; change one letter and it would not match.

What it does not prove: that the search found the best passage, or that the source article still says the same today.

2. Check that the published code is the code we tested Working today

Needs: Python 3 and a copy of the repository (git clone https://github.com/Anshul48/trace). A few seconds.

python3 tools/verify_freeze.py
python3 tools/check_receipts.py

The first re-computes the hash of each of the 207 files of the tested engine and compares it with the list we published. The expected end of the output is:

entries=207 ok=207 missing=0 mismatch=0

The second reads the records of the qualification run (gates passed, both probe modes, the digest of the frozen code) and checks they are consistent. Expected: receipts ok: gates, both probe modes, matched work, caps, freeze digest.

What it proves: the 207 engine files in the repository are byte-for-byte what our records say we tested. What it does not prove: that the tested engine is good, or anything about the larger library, which ran on our server.

3. Run the small reproduction Working today

Needs: Python 3.12 with numpy and blake3. About a minute for the check, longer for the full small run.

pip install numpy blake3
cd repro-20k
python3 prep_small_prefix.py verify-freeze --cand ../freeze-src/cand
python3 prep_small_prefix.py unpack --tar small-prefix-20k.tar.gz --data-dir data-20k
python3 prep_small_prefix.py verify --tokens 20000 --cand ../freeze-src/cand --data-dir data-20k

Expected: VERIFY PASS, with 88 documents, 144 passages and 0 cache misses. The folder's own README has the fourth step, which runs the tested engine's own protocol on those 20,000 tokens.

What it proves: the tested engine runs from a clean copy on real data, end to end, at 20,000 tokens. What it does not prove: any number from the big library. The small run's numbers are not the large run's, and it uses the earlier engine of the repository.

4. Run the explorer on your own computer Working today

Needs: Python 3 only. Downloads nothing.

./tools/run-trace.sh        # macOS or Linux
tools\run-trace.bat         # Windows

It serves the same pages you are reading from a local port and opens the explorer in your browser, with the recorded searches working offline.

What you cannot re-run yet

  • The measurement on the 99.9M-token library. The library and its search ran on our own server. The recorded searches are in the explorer, and the raw measurement files are on our build machine, not in this repository. A download for your own computer is planned, not built yet.
  • The 504.5M and 310.5M builds. Earlier tests of ours on a machine that has been shut down. Only their records exist: receipts/earlier-runs.
  • The 1.53 billion item. A separate October test; the files are not in this repository.
  • An outside check. Not built yet Nobody outside our team has re-run any of this. If you do, we would like to hear (see About).

What runs automatically on every change

Every push runs the tests in .github/workflows/ci.yml: the 207-file check, the record check, the backend tests, the small reproduction's check, the link and picture check, and a scan for file names that look like secrets. They show the repository is consistent. They are not a measurement of search quality.
