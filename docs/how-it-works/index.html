    What was and was not done

1. A pile becomes groups

Imagine a library with no shelves. Every new passage is dropped on the pile. TRACE files each passage with others that mean alike, so passages about vaccines end up near passages about the immune system.

No one writes labels or topic lists. Each passage is turned into a list of numbers that captures what it says, and passages with similar numbers are put in the same group. That is what we mean by “organizes itself”: the order comes from the passages, not from labels people add.

What we measured

  • Best matches stay together. In our tests a search's ten true best matches fall into about 7 groups on average, out of at most 10. If the same passages had been put into groups at random, it would be 10. (50 test searches, our library; the first quarter, where the other numbers on this site were measured, gave 6.5.)
  • A harder comparison. If you simply keep passages in the order they arrived, the ten best matches share about 8 groups. So the sorting step improves on arrival order, from about 8 to about 7, which is real but modest.
  • Same group, more alike. Passages in the same group are much closer to each other (0.55 on a 0 to 1 closeness score) than two random passages (0.045). The edges are soft, though: a passage is almost as close to a member of the next-nearest group (0.47) as to its own group-mates.

What we did not measure

On our 99.9M-token library the groups come from one ordinary sorting run (a standard method, k-means, five passes, once per quarter of the library). We measured how ordered the finished result is, not how it formed over time, and we have no curve of the order growing as the library grows. TRACE's own store, which is built to file passages as they arrive and repair itself, has the records of an earlier qualification run in the repository; that is the evidence for the process, and it is smaller than the main library.

One more honest limit: sorting the same collection at sizes from 10,000 to 200,000 passages showed order at every size, but it did not clearly grow with size. The largest set we sorted and measured holds 233,000 passages, so we make no claim about millions or billions, and we do not claim the order improves as the library grows.

Details and caveats: Evidence and limits. The raw output files are in receipts/order-measure.

2. A question wakes only a small part

Searching by meaning normally means comparing your question with every passage. TRACE first picks the groups most likely to hold the answer, then compares your question only with the passages inside them. The rest of the library is never scored for that question.

About 127 times less passage-scoring work (routing and building the groups are separate costs), and TRACE kept 0.9985 of exact search's top ten (1 would mean identical).

This is what we call sparse activation: only a small share of the memory is woken per question. What it does not mean: faster. At this size a plain scan answers sooner (see the limits), because TRACE also has to pick the groups, and our measured TRACE search is vector search only, with no keyword part. What it buys is less passage-scoring work, which should matter once a library is too big to scan in the time or memory you have. We have not measured where that crossover is.

The 0.79% was measured on one of the library's four equal parts, each about 203,000 passages. The same 50 test searches were not run as a random sample of all possible searches.

3. Every answer carries a record you can check

Each result comes with a checkable record: the article it came from, where in the article (the character span), the licence, and a fingerprint. The fingerprint (SHA-256) is a short code worked out from the exact text, and your browser can recompute it. If one letter changed, the code would not match.

What a match proves: the text on the page is the text that was sealed in the library. What it does not prove: that the search found the best passage, or that Wikipedia says the same today. The point is that you can check where an answer came from instead of taking it on trust.

Words we use, in plain words

Some of our words are borrowed from how brains are thought to work. We say “inspired by” because that is all we claim: we are not saying TRACE works like a brain.

Self-organization Prototype

Inspired by how order can arise without a conductor. In TRACE: the groups come from the passages themselves, not from labels people add. Measured: how ordered the finished groups are. Not measured: the order forming over time, or how it changes as the library grows.

Sparse activation Measured by us

Inspired by the idea that only a small part of a memory fires for a given cue. In TRACE: a question scores 0.79% of one of four equal parts. Measured on 50 test searches, on our library and method.

Recall

In plain words: bringing a stored passage back. We never use it as the name of a score.

A word we leave out

“Consolidation”, the settling of memories over time. We have no measured step that it would describe, so we do not use it.

TRACE

A memory that organizes itself. Research prototype, open source (Apache-2.0).
