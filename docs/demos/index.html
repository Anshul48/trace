TRACE: search that shows its work

TRACE is search that shows its work. In the film we pick a question in the real explorer, open a result’s checkable record, and press check: the browser works out the fingerprint of the exact text again, and it matches. Then we compare TRACE’s ten passages with those from exact search, which checks every passage: on our 50 test searches, TRACE looked at under 1% of the library and kept 99.85% of the exact top-ten results.

Honest limits. Ordinary keyword search did better on our test and answers faster, and exact meaning-based search did no better than TRACE. The public live server is off, so the explorer replays real recorded questions. No outside group has verified it, and the kit to run it on your own computer is planned, not built.

Scope of the under-1% figure: rows scored per search, counted in one of the library’s four sections, for the top ten results.

TRACE is search that shows its work. You ask in plain words. It finds the passages that match your meaning, and gives you a record you can check.

Ask an AI to search a huge pile of text, and you get an answer. But where did it come from? What did it miss? You can't tell.

So here is the real thing, running in a browser. The library behind it holds about 800 thousand passages.

Pick a question.

Results come up: passages that match what the question means, not just its words.

Click one.

Here is its checkable record: the article it came from, where in the article, and a fingerprint of the exact text.

Press check, and your own browser works out the fingerprint again. It matches.

Now the key question. Is this the same answer as the exact method, which checks every passage?

Here, the ten passages are the same, in the same order.

On our test searches, TRACE looked at under 1 percent of the library, and still found 99.85 percent of the exact answer.

Far less scoring work, and every result shows where it came from.

Try another question. Same idea: ranked passages, a record, and a side-by-side check.

An answer you can check, not just trust.

To use it, open the page in your web browser. There is nothing to install, and nothing to sign up for. It is a small page, and any computer with a web browser will do. A kit to run it on your own computer is planned, but not built yet.

Now, the honest limits. Ordinary keyword search did better on our test, and it answers faster. Exact meaning-based search, with no shortcut, did no better than TRACE. TRACE is for search by meaning that you can verify. The public live server is off, so this explorer replays real recorded questions. It has not been run on public benchmark tests yet, and no outside group has verified it.

ANIMA: an AI agent says “done”. Was it right?

ANIMA is a harness that lets an AI agent attempt a real bug fix, then checks the result with tests the agent did not see and cannot edit. In the film a stand-in agent says “done” and is wrong, the checker catches it, and the next helper up (a small local model, then Claude, then Codex) tries again. On nine real bug-fix jobs, seven were right the first time, and the checker caught the two wrong “done” answers, which the next helper then fixed.

Honest limits. It is tested for one kind of job only: fixing a bug against hidden tests. It is not a general job scheduler. The record check in the film confirms the links in the log; it does not re-run the nine jobs. The other parts (SST, STC and a shared memory with TRACE) are prototypes and are not shown.

Read the words

ANIMA is a harness that lets an AI agent attempt a real bug fix, and then checks whether the fix was right. Agents say, done. But were they right? Somebody still has to check, by hand. Here is a small demo bug report. The function says Sunday is not part of the weekend. A stand-in agent changes the code, and says: done. Now the real checker runs. It holds tests that the agent did not see, and cannot edit. Result: fail. The change counted Friday as weekend. The agent said done, and it was wrong.

The agent can also try to edit the tests, to make itself pass. The checker spots that, and rejects it.

So the next rung tries again. A rung is just the next agent up: a small local model, then Claude, then Codex. This time, the checker says: pass.

We ran this on nine real bug-fix jobs. Seven were right the first time. Two said done, and were wrong. The checker caught both, and the next rung fixed them. Here is one of those two, from the recorded log. The first agent said done. The checker disagreed. The next rung passed.

To check the record yourself, you need Python and git. No account, and no keys. First, copy the repository.

Then run the check. Each record in the log points back to the one before it, and here every link matches. Now change a single character in a copy. The break shows. This checks the record. It does not re-run the nine jobs.

On our laptop, a self-test must fail when we plant a fault. Publishing it is the next step.

What works today is the harness and its checker, tested for a single kind of job: fixing a bug against hidden tests. It is not a general job scheduler. Other parts are prototypes. SST tries many candidate fixes. STC turns a written spec into code. And a shared memory with TRACE, linked by a small test. We do not show them here.

To try it, start at the ANIMA repository on GitHub. The address is on screen. A checker the agent cannot see or edit decides. And if the agent was wrong, the next rung tries again.
