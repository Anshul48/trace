How this was built

One owner, one architect, many workers.

TRACE was made by a small team that works with AI tools, and we say plainly how. This page gives the counts. It does not claim who wrote what share of the code.

Three layers

  1. The owner set the direction, decided what to claim, and approved or rejected results.
  2. The architect is Claude, from Anthropic. It planned the work, wrote briefs, checked results and kept the records straight.
  3. The workers are automated agents that took a written brief and produced a result file. Most worker jobs ran on Meta's Muse Code tool.

Muse Code as our main worker tool

Muse Code (version 1.4.14) was our main automated worker tool. From 1 to 4 November 2026 we recorded 670 worker jobs on two machines (a laptop and a cloud machine): 619 finished, 22 failed and 21 were cancelled, and 8 were still running when we counted. The summed time of all attempts is about 170 hours; jobs ran in parallel, so that is not elapsed time.

All but two of the job records name the model muse-spark-1.3, at maximum reasoning effort; two used muse-wonder-1.0. About nine in ten worker attempts ran on Muse subscription accounts, and about one in ten on a Meta API key.

The jobs covered TRACE, ANIMA and Reflex work, film production, documentation, tests and infrastructure. One example with a written record: a worker job encoded the 812,545-passage library on a laptop graphics card in 1,002.6 seconds. The build report for the frozen engine fork in this repository (freeze-src/BUILD-REPORT.md) names Muse as its builder. None of the repository's commit messages mention Muse, so the git history alone does not show it.

How a worker job went

  1. A written brief with the goal, the files it may touch and what it must not do.
  2. A worker runs it on its own, without a person watching.
  3. A result file comes back with what it did and what is unverified.
  4. The architect and the owner review it before anything is claimed. Several of our public numbers were corrected at this step (see Corrections).

Meta products: what was used, what was not

  • TRACE's search itself uses no Meta model. Its text encoder is all-MiniLM-L6-v2, which is not from Meta. PyTorch, an open-source library created at Meta, ran the encoding of the library.
  • We also called SAM 3.1, Muse Spark vision, Muse voice and Muse Image in small, recorded, exploratory experiments on synthetic screenshots, for the Reflex project.
  • We found no Llama or other Meta open-weights model in our code, and we do not say what family the Muse models belong to.
