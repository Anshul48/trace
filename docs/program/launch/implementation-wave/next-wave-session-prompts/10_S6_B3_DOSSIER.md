# Session 10 - S6 B3 Certification Manifest and Foundation Dossier

Read the shared bootstrap prompt first. Start only after the human owner has
recorded P-005 and all referenced artifacts remain immutable and available.

## Mission

Assemble the B3 certification manifest and a factual Foundation Gate dossier.
This session packages evidence; it does not promote the system.

## Direction

- Bind admitted data/rights, code/package commits, model/provider identities,
  query/judgment/evidence mappings, runtime/hardware, configurations, receipts,
  result hashes, and retention locations.
- Reject missing, contradictory, or non-reproducible fields rather than
  smoothing them over.
- State evidence and limitations separately for durable memory,
  self-organization, retrieval accuracy, bounded resources, and 100K
  readiness.
- Label every condition passed, blocked, or not attempted. Never call a
  partial dossier production-ready.

## Suggested subagents

Use read-only manifest-integrity, statistics-reproduction, and dossier-
consistency reviewers. The S6 owner controls only the B3/dossier artifact.

## Exit

Write a complete B3 handoff and Foundation dossier with a precise list of
remaining blockers. Hand off only to S0 R2 for gate review.

## B3 manifest sections

The assembled manifest must bind, with hashes and versions:

- human decisions P-001, P-002, P-003, P-004, and P-005;
- dataset source records, licenses/rights, raw and normalized manifests;
- native query, judgment, document, segment, and evidence mappings;
- runner source/tag, package/dependency artifacts, and Trace/TL commits;
- model/provider/embedding fingerprints and configuration;
- worktree/source identity, hardware, OS/runtime, and parallelism;
- V1a/V1b receipts, implementation tests, migration checks, and limitations;
- baseline result files, per-case outputs, aggregate outputs, retention paths,
  and output hashes;
- explicit fallback/mock/synthetic/TLS and certification-eligibility fields.

Reject the manifest if fields are missing, contradictory, mutable, or only
described in chat. Do not rewrite prior receipts to make them agree.

## Foundation dossier structure

For each of the five promises, list evidence, authority level, verifier,
input/output hashes, supported environment, limitations, and status:

1. durable source memory and recovery;
2. correct self-organization and provenance;
3. retrieval accuracy and evidence grounding;
4. bounded performance and resource economics;
5. readiness for a real 100K corpus.

Add a claim-boundary section explicitly excluding public SOTA, production,
PostgreSQL/external-index, distributed, 1M, or consumer claims not supported
by the dossier.

## Review discipline

Use read-only manifest, statistics, and claim-boundary reviewers. Resolve
contradictions by marking the dossier blocked or not attempted; never infer a
pass from a green test count. The S6 owner cannot approve P-005 or the
Foundation Gate.
