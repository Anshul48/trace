# Session 4 - S5 V1a Benchmark Integrity Verification

Read the shared bootstrap prompt first. Start only after the B1.1 handoff
names a clean immutable benchmark commit and verifier lease.

## Mission

Independently prove that the certification runner fails closed under the frozen
negative matrix. This is an integrity test, not a public benchmark run.

## Direction

- Use a fresh verifier checkout of the finalized B1.1 commit, a verifier-owned
  environment, and isolated result/cache paths.
- Freeze the test configuration, manifests, and expected error-receipt matrix
  before testing.
- Deliberately exercise every forbidden path named by the S5 brief.
- For each case, prove the block/failure, expected receipt, and absence of a
  certification-eligible result or partial aggregate.
- Preserve unexpected success as failure evidence. Do not patch the runner or
  relax the matrix.

## Suggested subagents

Use read-only matrix reviewers or disjoint test executors if useful. Keep one
verifier-owned aggregator responsible for receipt inventory and final evidence.

## Exit

Write the V1a handoff with input hashes, commands, actual/expected receipts,
output inventory, uncovered conditions, and an exact claim boundary. A passing
matrix does not certify data quality, retrieval quality, lifecycle safety, or
scale.

## Negative matrix execution

Use the cases in 15_S5_INDEPENDENT_VERIFIER.md as the frozen minimum. The
matrix should separately exercise:

- missing source identity and editable/unpinned Trace-Lite import;
- mock/default provider and unavailable provider/model;
- missing, unadmitted, corrupt, or checksum-mismatched data;
- synthetic substitution and insecure TLS retry;
- indexing, organization, and query exception swallowing;
- forced flat-search fallback;
- empty positive retrieval versus explicit abstention;
- missing evidence mapping and fabricated organization/source coverage;
- unstable query-ID pairing;
- malformed or missing run/result/error manifests;
- metric/output failure and partial aggregate production.

For every case capture case ID, setup manifest hash, command, expected receipt,
actual receipt, output directory inventory, certification_eligible value, and
whether any result could be mistaken for a valid score. An exception alone is
insufficient if a fallback or partial result survived.

## Isolation and review

The verifier owns its clone, environment, fixtures, result root, and command
log. Do not import from an arbitrary developer checkout. Do not reuse the
implementation test database or provider cache. A read-only helper may inspect
receipt schemas or recompute output inventory, but no helper may alter the
runner or expected outcomes.

## Acceptance

Accept only exact tested properties. Mark the run blocked when a provider,
dataset, package, or transport prerequisite is unavailable. Preserve an
unexpected success as failure evidence and hand it back for a new repair
packet; do not patch it in place.
