# Session 7 - S3 TR2 Temporal and Revocation Implementation

Read the shared bootstrap prompt first. Start only after the human owner has
recorded P-004 with the temporal, revocation, and erasure contract.

## Mission

Implement the accepted P-004 contract in a fresh Trace worktree without
rewriting prior migrations or silently changing source-truth semantics.

## Direction

- Treat event time, valid time, historical policy, supersession, revocation,
  tombstone, and erasure decisions as fixed requirements.
- Preserve immutable Spine evidence and make historical projection selection
  explicit; never silently answer a historical query from the current release.
- Use additive/forward-only migration discipline and preserve workspace/policy
  isolation.
- Add focused tests for the accepted temporal contract and clear diagnostics
  for unsupported or unavailable historical projections.
- Record what was exercised locally versus what still requires independent
  PostgreSQL, RLS, or external-index verification.

## Suggested subagents

Use read-only contract reviewers for migration compatibility and temporal fault
cases. Only the S3 writer changes the leased Trace worktree.

## Exit

Commit TR2, record migration and runtime identities, exact decision reference,
tests, limitations, and the fresh V1b temporal-verification dependency.

## P-004 input contract

Before implementation, convert the human decision into a signed-off checklist
for event/system time, valid/effective time, version and supersession chains,
contradiction handling, revocation, tombstones, privacy erasure, historical
authorization, as_of_event release selection, and unavailable-history
diagnostics. Any unresolved dimension blocks implementation.

## Implementation sequence

Map each selected semantic to immutable Spine events, release metadata,
projection selectors, policy checks, and evidence bundles. Preserve prior
versions and explicit provenance. Ensure a historical query cannot silently
use the current projection. Implement forward-only/additive migrations with a
clear upgrade, downgrade/rollback, and replay story. Keep current
authorization boundaries distinct from historical policy evaluation as the
decision requires.

Add focused tests for valid-time intervals, supersession and contradiction,
soft revocation, tombstone filtering, historical visibility, erasure
receipts/content redaction, denied historical access, missing historical
release, and release/source revision identity in evidence bundles. Exercise
SQLite and any available PostgreSQL/RLS path separately. Do not call a local
test a deployment proof.

## Subagent boundaries

Use a temporal-contract reviewer, migration/replay reviewer, and adversarial
privacy/policy reviewer if useful. They may inspect or test their disjoint
scope but may not invent semantics or edit migration history outside the
lease.

## Required handoff

Include P-004 decision hash, migration checksums, code commit, temporal test
matrix, source/release evidence samples, unsupported infrastructure, rollback
status, and the exact V1b temporal-verifier input manifest.
