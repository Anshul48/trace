# Session 6 - S2 TL2 Bounded Graph Implementation

Read the shared bootstrap prompt first. Start only after the human owner has
recorded P-002 with concrete graph and PPR budgets.

## Mission

Implement the accepted bounded-association policy in a fresh Trace-Lite
worktree, preserving the candidate/active lifecycle proven by L1.

## Direction

- Treat the recorded P-002 decision as binding; do not choose substitute
  thresholds or broaden the graph mechanism.
- Apply the policy to high-DF filtering, degree/neighbor selection, PPR work,
  deterministic behavior, telemetry, and overflow handling as approved.
- Ensure candidate graph state remains isolated until validation and activation.
- Add focused tests and measurement evidence for the approved invariants.
- Preserve Beta APIs and existing regression behavior unless the decision
  explicitly authorizes a compatible change.

## Suggested subagents

Use read-only reviewers for budget enforcement and adversarial high-DF cases.
One leased writer owns implementation changes; a helper must not silently tune
parameters or alter public contracts.

## Exit

Commit the bounded implementation in its isolated worktree, record exact
policy/configuration identities, tests, measurements, limitations, and the
fresh V1b graph-verification dependency.

## P-002 input contract

Before coding, quote or hash the human decision record and extract an
implementation checklist containing:

- high-DF/common-term cutoff rule;
- maximum degree and deterministic neighbor choice;
- edge admission, weighting, and deduplication policy;
- PPR node, edge, depth, and total work budgets;
- query-time timeout and overflow behavior;
- memory, latency, and telemetry requirements;
- failure behavior when a bound is exceeded.

If the decision leaves a value open, stop and ask the coordinator to mark the
packet blocked. Do not fill the gap from a recommendation in a measurement
brief.

## Implementation and verification sequence

First inspect L1's candidate/active selectors and graph build identity.
Implement the smallest compatible policy surface. Keep graph projections
versioned and invisible until validation/activation. Add deterministic
fixtures for common terms, high-degree terms, duplicate edges, empty graphs,
budget overflow, cancellation, replay, and rollback. Measure edge counts,
degree distributions, build/query work, latency, memory, and overflow
receipts on the declared corpus before reporting success.

Run the existing Trace-Lite regression/lifecycle suite and the new focused
suite with external writable scratch paths. Compare incremental/replay and
full/rebuild behavior where P-002 requires it. Do not alter the canonical
Spine, choose a new graph family, remove Beta APIs, or claim scale beyond the
measured environment.

## Subagent boundaries

A policy reviewer may check the implementation against the decision. An
adversarial-measurement reviewer may generate high-DF fixtures and recompute
telemetry. A compatibility reviewer may inspect public API/regression impact.
Only S2's leased writer changes code; helpers cannot tune policy values.

## Required handoff

Include P-002 decision hash, code commit, configuration hash, before/after
graph statistics, budget receipts, tests, environment, limitations, and the
exact V1b graph-verifier input manifest.
