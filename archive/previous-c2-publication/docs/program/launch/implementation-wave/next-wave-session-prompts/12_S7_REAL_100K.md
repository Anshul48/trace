# Session 12 - S7 Real 100K Scale Gate

Read the shared bootstrap prompt first. Start only after an accepted Foundation
Gate and a dedicated S7 lease, corpus admission record, and capacity plan.

## Mission

Execute the first real 100K text-memory experiment and measure its declared
correctness, recovery, performance, resource, and cost properties.

## Direction

- Use an admitted real text corpus with immutable source/data manifests.
- Keep all scale artifacts in dedicated external paths and preserve prior
  baseline evidence.
- Define and record the exact ingestion, rebuild, failure/recovery, query,
  cold/warm, and resource-measurement protocol before execution.
- Measure evidence integrity, retrieval behavior, crash/replay/rebuild
  recovery, latency, QPS, memory, disk, graph work, and cost.
- Separate observed facts from untested distributed, 1M, or production claims.

## Suggested subagents

Use disjoint observers for resource telemetry, recovery/fault evidence, and
result-manifest integrity. One S7 owner controls the experiment and final
handoff; helpers do not adjust workloads or thresholds silently.

## Exit

Deliver a 100K gate dossier with hashes, offsets, coverage, topology, exact
protocol, raw metrics, failures, and a recommendation for a human go/no-go
decision. Do not begin 1M work in this session.

## Preflight and corpus admission

Record the accepted Foundation Gate hash, S7 lease, corpus/source/license
record, raw and normalized hashes, expected expanded size, free space,
working headroom, hardware, runtime, provider/model identity, and resource
limits. Verify that the corpus is real, downloadable/license-aware, and
distinct from the internal 320-case regression fixture. If capacity, rights,
source identity, or provider access is unresolved, stop blocked.

## Execution phases

1. Freeze the run manifest and measurement protocol.
2. Ingest the real corpus while preserving source bytes, offsets, atom hashes,
   revision identity, and evidence mappings.
3. Build/rebuild candidate projections and verify validation/activation and
   predecessor retention.
4. Run normal, cold, warm, incremental, replay, and crash/recovery scenarios.
5. Run the declared query classes with stable IDs and evidence bundles.
6. Capture p50/p95 latency, QPS, RSS, memory, disk, graph work, build time,
   recovery time, failed/blocked cases, and cost.
7. Re-run selected checks from the recorded manifest and compare output hashes.

Keep correctness, recovery, quality, latency, resource, and cost evidence
separate. Do not silently reduce corpus size, query count, evidence coverage,
or fault scope to make a run complete.

## Subagent boundaries

Use disjoint telemetry, recovery/fault, and manifest-integrity observers.
Observers may collect or recompute evidence but may not alter workloads,
thresholds, source data, active pointers, or result files.

## Exit criteria

The handoff must state corpus size and coverage, exact source/projection
identities, topology and orphan checks, evidence/provenance coverage,
incremental/full and replay/rebuild parity, resource/cost distributions,
failures/limitations, and a human promotion recommendation. A 100K result
does not authorize 1M automatically.
