# Session 9 - S6 Real Baselines and P-005 Decision Brief

Read the shared bootstrap prompt first. Start only after V1a, D2b, and the
applicable V1b sub-gates are accepted or explicitly blocked with a documented
claim boundary.

## Mission

Run reproducible real-data baselines through trace-bench and prepare, but do
not decide, P-005 numerical release thresholds.

## Direction

- Use only the canonical benchmark runner and admitted normalized datasets.
- Bind each run to source/package/data/query/evidence/configuration/model/
  hardware identities and complete receipts.
- Keep direct, semantic, multi-hop, chronology, abstention, organization, and
  vector-operations capability lanes separate.
- Capture positive, abstention, excluded, failed, and blocked denominators.
- Derive a P-005 proposal from observed baseline distributions, including
  statistical method, practical effect, latency/resource budgets, and failure
  handling.

## Boundaries

Do not select thresholds, claim certification, blend BigANN results into
text-memory quality, modify product code, or use a mock/synthetic/fallback
path.

## Suggested subagents

Use disjoint query-class/statistics reviewers and a manifest reviewer. They
may recompute immutable outputs but may not alter canonical results.

## Exit

Deliver immutable baseline artifacts and a P-005 decision brief. Stop for the
human owner to record P-005 before B3 is assembled.

## Baseline run design

Freeze a run manifest before executing. It should identify runner commit/tag,
Trace-Lite and Trace artifact identities, raw and normalized dataset hashes,
query/judgment/evidence map hashes, model/provider/embedding fingerprints,
configuration, hardware, runtime, parallelism, cold/warm state, resource
limits, and output root.

Run the declared capability lanes separately:

- direct/source lookup;
- semantic/vector retrieval;
- hierarchical/organization behavior;
- multi-hop and compositional evidence;
- chronology/revision/contradiction;
- abstention and unsupported queries;
- operations/vector scale.

For every case retain native query ID, status, retrieved IDs, evidence IDs,
offsets/hashes, latency, resource samples, error/abstention/exclusion state,
and correlation ID. Use stable query-ID pairing for comparisons. Do not merge
denominators across query classes or convert empty positive retrieval into
abstention.

## P-005 brief contents

Propose, without approving:

- primary and secondary metrics by lane;
- denominators, exclusions, and blocked-case handling;
- cold/warm latency and throughput budgets;
- memory, disk, graph-work, and cost budgets;
- minimum evidence/provenance coverage;
- paired comparison, confidence, significance, and practical-effect rules;
- reproducibility, retention, and failure requirements.

Base proposals on the actual baseline distributions and resource observations.
Call out where the data is insufficient for a threshold. Keep certification
eligibility false until the human decision and B3 checks are complete.

## Subagent boundaries

Assign disjoint query-class runners, a statistics re-computation reviewer, and
an artifact/manifest reviewer if needed. Helpers may read immutable outputs and
recompute metrics but may not alter the canonical run, thresholds, or
exclusion rules.
